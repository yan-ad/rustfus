# RustFus iced UI audit 002

Date: 2026-10-27
Mode: after implementation. No audit-driven fixes applied without approval.

## Scope

Reviewed the real macOS dark-mode capture at `artifacts/rustfus-iced-preview.png`, component source integration, theme subscriptions, and automated tests. Controls use r4ai's `shadcn-iced` 0.3.0. The displayed UC300 disk is real, not a fixture.

## Findings

1. **HIGH verification gap · R-32 Keyboard Accessibility** — Full keyboard-only operation of the linked component library has not been manually exercised. Verify Tab/Shift+Tab, select-menu navigation/dismissal, partition radio arrow keys, advanced-property disclosure, ISO dialog cancel, and Close.
2. **HIGH verification gap · R-34 Every Theme You Ship Must Work / R-35 Verify Before You Deliver** — The current OS dark mode was visually checked and theme mapping/state preservation pass automated tests, but the light-mode rendering and a real OS theme change while running have not been manually checked on every platform. Verify both modes and live switching without losing selections.
3. **LOW · R-05 Layout and Page Structure** — The capture shows the vertical scrollbar over the right edge of the form. Consider reserving scrollbar space so right-hand control borders are unobstructed; the footer is already fixed and visible.

## Confirmed

- Button, Select, and RadioGroup are from the exact user-linked component library, including disabled future selectors.
- No theme configuration UI exists. OS theme query and subscription drive the palette.
- System text font is resolved natively and used by shadcn text variants; bundled Geist/Inter features are disabled. Only Lucide icons are embedded.
- No manual refresh button or refresh interval/timer label appears.
- Device loading/empty/error states exist; scan failures clear stale selections.
- Disk-writing and DOS creation remain disabled; the preview makes no bootability guarantee.
